# Сбор журнала и логов для диагностики

Ядро умеет непрерывно складывать системный журнал и логи продукта в одно
хранилище за последние сутки. Это нужно, когда сбой уже произошёл: по архиву
можно объяснить, что делало ядро, что видела сеть и что показывал UI.

Сбор выключен по умолчанию и переключается в приложении: **Diagnostics →
Debug capture**. Тот же переключатель доступен из CLI:

```bash
sudo kikimora-core diagnostics on
sudo kikimora-core diagnostics status
sudo kikimora-core diagnostics off
sudo kikimora-core diagnostics bundle
```

На Windows CLI вызывается так же (без `sudo`), путь к сокету по умолчанию
совпадает с сервисом.

## Что собирается

| Источник | Содержимое |
|---|---|
| `journal-*` | `journalctl` по юнитам `kikimora-core`, `leshy`, `kikimora-leshy-dns`, `NetworkManager` |
| `kernel-*` | ядро Linux: линки, маршруты, DNS и ошибки драйверов |
| `eventlog-system-*`, `eventlog-application-*` | журналы событий Windows (System и Application) |
| `logs-*` | файлы логов ядра, Toad-процессов, Leshy и настольного UI |
| `state-*` | снимок состояния: версия, режим, роли, маршруты, адреса, DNS |

Логи UI пишутся всегда в `Kikimora/logs/kikimora-ui-ГГГГММДД.log` рядом с
пользовательскими данными приложения (`%LOCALAPPDATA%\Kikimora\logs`,
`~/.local/share/Kikimora/logs`). Сборщик копирует только новые строки, поэтому
файл можно читать и во время сбора.

## Где лежит и сколько хранится

```
Linux:   /var/lib/kikimora/core/diagnostics
Windows: C:\ProgramData\Kikimora\state\diagnostics
```

Файлы почасовые. Всё старше 24 часов удаляется при каждом сборе, общий размер
хранилища ограничен 256 МБ: при переполнении первыми уходят самые старые файлы.
Один источник за один проход добавляет не больше 1 МБ, чтобы всплеск логов не
раздувал архив.

## Архив

```bash
sudo kikimora-core diagnostics bundle
```

Команда собирает все файлы хранилища в `kikimora-diagnostics-ГГГГММДД-ЧЧММСС.zip`
и печатает путь. Этот файл можно приложить к отчёту о проблеме.

## Приватность

Архив содержит имена интерфейсов, адреса, маршруты, списки доменов и вывод
`ip`/`ipconfig`. Ключей и паролей там нет: сборщик не открывает конфигурации
туннелей, он копирует логи и снимок состояния. Перед публикацией архив всё
равно стоит просмотреть: в системном журнале может быть больше, чем ожидается.
