Rootless/privileged execution split
-----------------------------------
The previous design exposed real kernel modes through run-rootless.sh. Repeated
execution showed that the current executor cannot create the first required
mapped user namespace:

  unshare: write failed /proc/self/uid_map: Operation not permitted

Repeating route-parking, multi-toad, orchestration-acceptance and xray-interop
through the rootless wrapper therefore added no evidence beyond the same
capability failure.

Since 5ad097a/36de5ff the execution contract is explicit:

  bash linux/tests/toad/run-rootless.sh model
    deterministic no-sudo executor gate

  bash linux/tests/toad/run-rootless.sh probe
    capability diagnostic only

  bash run-privileged-gates.sh
    authoritative operator kernel/network integration suite

run-rootless.sh no longer exposes kernel/network gate modes. Calling an old
kernel mode such as route-parking exits with usage status 2 and points to the
privileged runner.

Useful rootless-runner guarantees moved to the privileged runner
----------------------------------------------------------------
run-privileged-gates.sh now owns:

- user-owned incremental build-only before sudo is acquired;
- a dedicated user-owned build cache:
    build/toad-privileged-user-<uid>
- stale Kikimora fixture cleanup before the suite and before each gate;
- final cleanup through EXIT trap;
- route-parking;
- multi-toad;
- orchestration-acceptance;
- hermetic official-Xray interop;
- per-gate artifacts in .gigacode/gate-*.log;
- nonzero suite exit status if any gate fails;
- host network-state snapshot after initial cleanup and after final cleanup;
- failure if host link/default-route/policy-rule/named-netns state is changed by
  the privileged suite.

run-isolated.sh remains non-self-elevating. Direct netadmin modes require uid 0
with usable CAP_NET_ADMIN and point operators to run-privileged-gates.sh.
