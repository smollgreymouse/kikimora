# Phase 1 — make Linux package install-complete, not only payload-complete

Current package stages a template only at:

`/usr/share/kikimora/orchestration-ownership.conf`

but the installed service executes:

`--ownership-config /etc/kikimora/leshy/orchestration-ownership.conf`.

That means a fresh package install can contain the service without the config path it references.

## 1.1 Install a default ownership config safely

Package must create:

`/etc/kikimora/leshy/orchestration-ownership.conf`

with the existing legacy-safe defaults from `linux/files/orchestration-ownership.conf`.

Rules:

- treat it as user/admin configuration;
- upgrades must not overwrite an existing file;
- never change ownership to Go during package install;
- keep the copy under `/usr/share/kikimora/` as the packaged default/template.

Implement through Debian maintainer scripts or conffile semantics. Preferred behavior:

```text
if /etc/kikimora/leshy/orchestration-ownership.conf missing:
    install default legacy/external/legacy config
else:
    preserve existing file byte-for-byte
```

Also ensure `/etc/kikimora/toads` and required state/config parent directories exist with safe modes, without generating fake Toad configs.

## 1.2 Add Debian post-install integration

Add `DEBIAN/postinst` generated by the canonical stage builder.

Required actions:

- `systemd-sysusers` for packaged sysusers config when available;
- `systemd-tmpfiles --create` for packaged tmpfiles config when available;
- `systemctl daemon-reload` when systemd is present;
- do **not** start/enable core;
- do **not** run cutover;
- do **not** mutate existing desired state;
- do **not** restart NetworkManager automatically.

Add conservative `postrm` daemon-reload if needed.

Do not put secrets into maintainer scripts.

## 1.3 Dependency contract

OpenConnect is a production-supported backend and uses the external `openconnect` executable.

Make the Linux package contract explicit:

- either add `openconnect` to Depends;
- or if intentionally optional, add it to Recommends and make `kk verify` report clearly that OpenConnect roles are unavailable until installed.

Prefer `Depends: openconnect` for the current all-protocol product artifact unless an existing product policy says otherwise.

Never depend on `ocserv` in the product package.

## 2.1 CLI version

`kikimora version` from the staged package must equal root `VERSION` exactly.

## 2.2 Core and Toad version

Keep `kikimora-core version` wired via linker variable, but make the value exactly root `VERSION` with one consistent prefix policy.

Add an explicit `version` command to `kikimora-toad` if none exists.

Use a Toad-specific linker variable, e.g. `toadVersion`; do not pass `-X main.coreVersion=...` to Toad.

Required local smoke from extracted/staged binaries:


# Phase 4 — fix macOS package staging contract

Current macOS staging is not release-valid yet.

## 4.1 Do not package the Linux CLI without its runtime

Current `packaging/macos/stage-release.sh` installs `linux/kikimora` but does not install its CLI libraries, and the Linux CLI itself uses Linux-specific systemctl/ip behavior.

Do not ship that broken combination.

Use the existing macOS adapter as the starting point:

- `macos/kikimora`;
- `macos/lib.sh`;
- required macOS support scripts/files.

Then add only the Go-core control commands required by the current macOS product contract, or write a small macOS-specific wrapper.

If a clean macOS `kk` contract cannot be completed without broader CLI redesign, STOP and write a focused packet instead of shipping Linux CLI on macOS.

## 4.2 Fix launchd core arguments

`macos/files/com.kikimora.core.plist` currently lacks the production persistence/ownership arguments used on Linux.

Add/verify:

- `--ownership-config` with the macOS installed ownership config path;
- `--state-dir` with a persistent macOS state path;
- correct `--config-dir`;
- correct endpoint-provider path if still required;
- Go binary path exactly `/usr/local/bin/kikimora-core`.

Package a legacy-safe default ownership config for macOS and preserve it on upgrade.

Do not start Go ownership automatically from package installation.

## 4.3 Normalize Darwin architecture names

Map host architecture explicitly:

```text
uname -m x86_64 -> GOARCH=amd64, artifact arch=x86_64 (or a documented single naming convention)
uname -m arm64   -> GOARCH=arm64, artifact arch=arm64
```

Never pass `GOARCH=x86_64`.

Allow explicit `KIKIMORA_ARCH=amd64|arm64` for cross-build logic.

## 4.4 Use macOS-native checksum/archive tools

Do not assume `sha256sum` exists on stock macOS.

Use a helper:

```text
sha256sum if present
else shasum -a 256
```

Do not assume GNU tar flags (`--sort`, `--mtime`, `--owner`, `--group`, `--numeric-owner`) on macOS.

Use macOS-compatible archive creation (`ditto`, BSD tar-safe flags, or a portable helper). Reproducibility may be a later signing/release optimization; correctness comes first.

## 4.5 Fix actual Qt bundle name

Do not hard-code `$BUILD_DIR/Kikimora.app` unless CMake sets that exact bundle output name.

Either:

- set `OUTPUT_NAME Kikimora`/bundle properties explicitly in CMake;
- or copy the actual target-produced app bundle name.

Add a static assertion/test so packaging cannot silently reference the wrong bundle name.

## 4.6 Resolve obsolete installer drift

`macos/install.sh` previously referenced missing `kikimora-macos`.

Audit current file and remove all references to nonexistent source-tree files.

After canonical `.pkg` path exists:

- either make `macos/install.sh` a thin source/developer wrapper around canonical staging;
- or clearly deprecate it and test that it does not advertise missing files.
