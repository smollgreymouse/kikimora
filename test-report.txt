Relevant code audit
-------------------
AWG health has:
  recentHandshakeWindow = 30 seconds

However:
- AWG Backend.Validate() currently reports Healthy=true whenever the official
  AWG device/core is attached to the managed TUN
- Backend.Validate() does not require a recent handshake
- Toad RouteReady is derived from structural managed-interface readiness
- RouteReady therefore remains true when the AWG session is no longer connected

Consequently the Phase B failure cannot be dismissed as merely a 15-second
test timeout. The current validation contract itself does not make recent AWG
handshake/session reachability a requirement for Healthy/Ready validation.

The captured state already demonstrates this mismatch:
  session.connected=false
  state=Ready
  route_ready=true
  publication.published=true

No production behavior was changed in this verification pass.
